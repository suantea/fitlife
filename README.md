# FitLife

## 1. 应用理念
FitLife 面向健身爱好者与长期训练人群。传统健身软件要么功能冗余、学习成本高，要么过于简略、难以形成系统记录。FitLife 以“够用、清晰、可持续”为设计核心，融合训练记录与饮食记录，并内置 AI 助手：基于个人训练、饮食与身体数据给出建议。AI 功能需要自行配置 API，但提供图形化配置界面，操作简单、上手快。

## 2. 功能与使用方式
- 训练模板与计划
  - 创建训练模板（训练天数、休息周期、训练部位与动作）
  - 模板灵活调整，支持随时修改
  - 依据模板自动生成每日训练计划
- 训练记录与引导
  - 训练中计时与组间休息提醒
  - 记录组数、次数、重量、备注等数据
  - 训练记录支持编辑与删除
- 饮食记录与建议
  - 记录每日食物与饮品
  - 自动统计热量与宏量营养素
  - 支持自定义食物与常用食物
  - 支持碳水循环计划配置
- AI 助手
  - 基于训练/饮食/体测等结构化数据给出建议
  - 提供系统化提示词与知识库辅助
  - 需配置自己的 AI API Key（界面配置）

**快速使用流程**
1. 进入“我的/设置”，填写基础信息（身高体重、目标等）
2. 在“训练模板”中创建或编辑训练计划
3. 在“训练”页开始训练并记录组数数据
4. 在“饮食”页记录食物并查看宏量营养素
5. 在“AI 助手”中配置 API Key，获取每日建议

**APK 下载**
- 推荐通过 GitHub Releases 发布 APK，并在 Release 说明中提供下载链接
- 不建议直接把 APK 提交到仓库主分支（体积大、拉取慢）

## 3. 代码架构与不足
**架构概览**
- `app/`：页面与路由（Expo Router）
- `components/`：可复用 UI 组件
- `lib/`：数据模型、训练/饮食逻辑、AI 逻辑与本地存储
- `docs/`：知识库文档（AI 引用）
- `server/`：可选后端（tRPC + Drizzle）
- `drizzle/`：数据库 schema 与迁移

**不足与改进方向**
- 默认以本地数据为主，缺少多端同步与云备份
- AI 需自备 API Key，成本与稳定性受第三方影响
- 缺少更强的数据可视化与长期趋势分析
- 部分功能仍在打磨（例如更细致的模板与计划优化）
